## §4 功能 3 — 复习页"已掌握"按钮

### 现状
- 复习页顶栏 actions 只有收藏按钮
- 已掌握定义：`(latest.nextReviewDate == -1L) || (latest.correctCount >= 3)`
- 今日判定：`latest.nextReviewDate ∈ [today00:00, today23:59]`

### 变更

**ReviewScreen.kt**：
- 顶栏 actions 增加金色 ✓✓ 图标按钮（仅在 `showResult == true` 时显示）
- 位置：收藏按钮右侧
- 图标：使用 `Icons.Default.CheckCircle` 或新增矢量图

**ReviewViewModel.kt**：
- 新增 `markAsMastered(mistakeId: Long)`：
  ```
  viewModelScope.launch {
    val cal = Calendar.getInstance()
    cal.set(HOUR_OF_DAY, 0); cal.set(MINUTE, 0); cal.set(SECOND, 0); cal.set(MILLISECOND, 0)
    cal.add(DAY_OF_MONTH, 1)
    val tomorrowStart = cal.timeInMillis
    repository.insertReviewRecord(
      ReviewRecord(
        id = 0,
        mistakeId = mistakeId,
        reviewDate = System.currentTimeMillis(),
        result = ReviewResult.CORRECT,
        nextReviewDate = tomorrowStart,
        correctCount = 3
      )
    )
  }
  ```

### 行为验证（用现有 HomeViewModel 逻辑）
- **今天**：
  - latest = 新记录
  - todayRecord 查找：reviewDate=now ∈ today → 命中
  - isReviewed = (todayRecord.result != SKIP) = true → 显示在今日列表，标签"✓ 正确"
  - nextReviewDate=明天00:00 不在 today 范围 → 不作为"今日新题目"
  - 结果：**今天仍保留**（显示为已复习 ✓ 正确）
- **明天起**：
  - latest = 新记录
  - isMastered = (correctCount ≥ 3) = true → 排除
  - 不进入今日/逾期 ✓
- **BrowseViewModel 已掌握模式**：
  - correctCount=3 → 出现在已掌握列表 ✓
- **BrowseScreen 答错归零逻辑**：
  - 已掌握题被答错 → correctCount=0 → 回到复习循环（行为不变）

### 边界
- 仅 `showResult == true`（用户已提交答案）时显示
- 重复点击：插入多条相同记录（last one wins，符合现有模式）

## §6 功能 5 — 录入时间选项

### 现状
- `ImportViewModel.saveMistake()` 第 323 行：`createdAt = existingMistake?.createdAt ?: now`
- `nextReviewDate = now + 5天`

### 变更

**ImportUiState** 新增字段：
```

```

**ImportViewModel.kt**：
- 新增 `setEntryDate(epochMillis: Long)`：归一化为当日 00:00 后写入 state
- `saveMistake()` 改造：
  ```
  val cal = Calendar.getInstance()
  cal.set(HOUR_OF_DAY, 0); cal.set(MINUTE, 0); cal.set(SECOND, 0); cal.set(MILLISECOND, 0)
  val today00 = cal.timeInMillis
  val finalCreatedAt = state.entryDate ?: today00
  val finalNextReviewDate = finalCreatedAt + 5 * 86400000L
  mistake.copy(
    createdAt = finalCreatedAt,
    ...
  )
  ReviewRecord(nextReviewDate = finalNextReviewDate, ...)
  ```
- `loadMistakeForEditing()`：编辑模式下 `entryDate = mistake.createdAt`

**ImportScreen.kt**：
- 新增组件 `EntryDateRow`：
  - 显示"录入时间：YYYY-MM-DD"
  - 右侧日历图标
  - 整行 `clickable` → 弹出 `DatePickerDialog`
- 位置：在"标题"输入框之前
- 用 Material3 `DatePicker` + `DatePickerDialog`

### 行为验证
- 默认（不选）：今天 + 5天（与现有行为一致）
- 选过去日期（如 5-25）：createdAt=5-25 00:00, nextReviewDate=5-30 00:00
  - 6-1 看到：HomeViewModel 判定为"逾期 2 天"
  - 5-30 看到：判定为"今日"
- 选未来日期（如 6-5）：createdAt=6-5 00:00, nextReviewDate=6-10 00:00
  - 6-5 看到：未到复习时间，不在今日/逾期
  - 6-10 看到：判定为"今日"
- 编辑已有错题：entryDate 初始化为原 createdAt，编辑不改变原意

### 标题自动生成
- 现有逻辑：`SimpleDateFormat("yyyy-MM-dd").format(Date())` + 当日序号
- 改为：`format(state.entryDate ?: now)` + 该日序号
- 保持同日序号连续性

## §8 功能 7 — 图片放大 + 自适应大小

### 现状
- 复习页题目/答案图片：`AsyncImage` + `heightIn(max = 屏幕高度 * 0.66)` + `ContentScale.Fit`
- 多图用 `HorizontalPager`
- 点击图片无反应

### 变更

**新组件 1：`ui/components/ZoomableImage.kt`**
- 签名：`@Composable fun ZoomableImage(file: File, modifier: Modifier = Modifier)`
- 实现：
  - 状态：`scale: Float = 1f`, `offsetX: Float = 0f`, `offsetY: Float = 0f`
  - `Modifier.pointerInput(Unit) { detectTransformGestures { centroid, pan, zoom, _ -> ... } }`
  - `Modifier.pointerInput(Unit) { detectTapGestures(onDoubleTap = { ... }) }`（双击切换 1x ↔ 2.5x）
  - `Modifier.graphicsLayer(scaleX, scaleY, translationX, translationY)`
  - 缩放范围 0.5x ~ 5x
  - 拖动边界：缩放>1 时允许，缩放=1 时禁用
- 性能：使用 `coil.compose.AsyncImage` + `Modifier.graphicsLayer` 硬件加速

**新组件 2：`ui/components/ImagePreviewDialog.kt`**
- 签名：`@Composable fun ImagePreviewDialog(file: File, onDismiss: () -> Unit)`
- 全屏 `Dialog`（`DialogProperties(usePlatformDefaultWidth = false)`）
- 背景：纯黑 `InkStoneBlack`
- 内容：`ZoomableImage(file, modifier = Modifier.fillMaxSize())`
- 顶部：渐变蒙层 + 关闭按钮（点击/物理返回键）
- 可选：顶部显示"题目图片 2/5"页码

**新组件 3：`ui/components/AdaptiveImage.kt`**
- 签名：`@Composable fun AdaptiveImage(file: File, onClick: () -> Unit, modifier: Modifier = Modifier)`
- 自适应大小：
  - 用 `coil.compose.rememberAsyncImagePainter` 加载，配合 `IntrinsicSize` 测量
  - 或用 `ImageRequest.Builder` + `ImageResult.Metadata` 获得原始尺寸
  - 计算：已知原图 width/height，ratio = w/h
  - 在 `BoxWithConstraints` 中：测量 containerWidth
  - `displayWidth = containerWidth`（限宽）
  - `displayHeight = containerWidth / ratio`
  - 若 displayHeight > maxImageHeight（屏幕 2/3）：displayHeight = maxImageHeight，displayWidth = maxImageHeight * ratio
  - 整体高度取较大值（不裁剪）
- 点击 → 调用 `onClick`（弹 `ImagePreviewDialog`）
- 始终 `ContentScale.Fit`

**ReviewScreen.kt 替换**：
- 单图：原 `AsyncImage(model = File(path), heightIn(max = maxImageHeight), contentScale = Fit)` → `AdaptiveImage(file, onClick = { showPreview = File(path) })`
- 多图 `MultiImagePager` 中每个 page：同样替换为 `AdaptiveImage`
- 新增状态：`previewFile: File? = null`
- 末尾：`previewFile?.let { ImagePreviewDialog(file = it, onDismiss = { previewFile = null }) }`

**现有 maxImageHeight 变量**：保留但仅作为上限约束

### 行为
- 单张横长图（如 800x300）：宽 = 容器宽，高 = 容器宽 × 300/800（远小于 2/3 屏高）→ 上下有空白
- 单张竖长图（如 300x800）：高 = 容器宽 × 800/300，可能超过 2/3 屏高 → 限高，宽度相应缩
- 单张超长图（如 200x1000）：高 = 2/3 屏高，宽 = 2/3 屏高 × 200/1000（很小）→ 居中显示
- 任何情况都不裁剪
- 点击进入全屏预览：双指缩放/双击放大/拖动
